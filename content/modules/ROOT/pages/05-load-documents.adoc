= Load and Chunk Documents
:navtitle: 5. Load and Chunk Documents

_Estimated time: 15 minutes_

An HR assistant needs answers grounded in the organization's documents. In this
exercise, use a small fictional policy with a distinctive approval code. That
makes retrieval observable; a public policy question could be answered from the
model's training data alone. This is workshop data, not employment guidance.

== Know: Upload, embed, retrieve

Uploading parses a document into the document library. Embedding associates its
chunks with a workspace and stores their vectors. Querying retrieves matching
chunks before calling the assigned model. These are separate operations.
AnythingLLM's native embedding model runs in the workbench; the generation
model is accessed through the provisioned MaaS connection. An HTTP 200 from
an upload does not establish successful embedding or grounded generation.

== Do: Prepare a private working directory

[source,bash,role="execute",subs="attributes+"]
----
export ANYTHINGLLM_URL="$(oc get route anythingllm -n {project_name} -o jsonpath='https://\{.spec.host\}')"
echo "Generate your learner-instance API key at: $\{ANYTHINGLLM_URL\}/settings/api-keys"
----

Generate the key in that instance's settings, then enter it without echoing it
or placing its value in shell history. Use this same Terminal through Module 6.

[source,bash,role="execute"]
----
read -r -s -p 'AnythingLLM API key: ' ANYTHINGLLM_API_KEY; echo
export ANYTHINGLLM_API_KEY
umask 077
export RAG_EVIDENCE_DIR=$(mktemp -d "$HOME/rag-evidence.XXXXXX")
cd "$RAG_EVIDENCE_DIR"
cat > northstar-policy.txt <<'POLICY'
Northstar workshop policy, version LAB-2026-10.
Employees may request two paid learning days per quarter.
The approval code for a learning-day request is CEDAR-742.
Requests go to the employee's manager at least seven calendar days in advance.
This fictional document does not define remote-work allowances.
POLICY
----

== Do: Create a workspace and keep its returned slug

A repeated workspace name can produce a different slug. Use the returned value
instead of assuming that the name is also its URL.

[source,bash,role="execute"]
----
curl -fsS -X POST "$ANYTHINGLLM_URL/api/v1/workspace/new" \
  -H "Authorization: Bearer $ANYTHINGLLM_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"name":"hr-assistant"}' -o workspace.json
python3 - <<'WORKSPACE_PY'
import json, re
from pathlib import Path
data = json.loads(Path('workspace.json').read_text())
slug = (data.get('workspace') or {}).get('slug', '')
if not re.fullmatch(r'[a-z0-9][a-z0-9-]*', slug):
    raise SystemExit('STOP: workspace creation did not return a usable slug')
Path('workspace-slug.txt').write_text(slug)
print('PASS: workspace slug recorded')
WORKSPACE_PY
export WORKSPACE_SLUG=$(cat workspace-slug.txt)
----

Stop if any command fails; do not continue with an empty slug.

== Do: Upload the policy and use its returned location

[source,bash,role="execute"]
----
curl -fsS -X POST "$ANYTHINGLLM_URL/api/v1/document/upload" \
  -H "Authorization: Bearer $ANYTHINGLLM_API_KEY" \
  -F 'file=@northstar-policy.txt' -o upload.json
python3 - <<'UPLOAD_PY'
import json
from pathlib import Path
data = json.loads(Path('upload.json').read_text())
docs = data.get('documents')
if data.get('success') is not True or data.get('error') or not isinstance(docs, list) or not docs:
    raise SystemExit('STOP: document parsing did not succeed')
locations = [d.get('location') for d in docs if isinstance(d, dict)]
if len(locations) != len(docs) or any(not isinstance(p, str) or not p for p in locations):
    raise SystemExit('STOP: upload did not return document locations')
Path('embeddings-request.json').write_text(json.dumps({'adds': locations}))
print('PASS: returned document locations recorded; embedding is next')
UPLOAD_PY
curl -fsS -X POST "$ANYTHINGLLM_URL/api/v1/workspace/$WORKSPACE_SLUG/update-embeddings" \
  -H "Authorization: Bearer $ANYTHINGLLM_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @embeddings-request.json -o embeddings.json
python3 - <<'EMBED_PY'
import json
from pathlib import Path
data = json.loads(Path('embeddings.json').read_text())
if data.get('error') or not isinstance(data.get('workspace'), dict) or not data['workspace'].get('slug'):
    raise SystemExit('STOP: embedding request was not accepted; inspect the workbench privately')
print('PASS: embedding request accepted; verify workspace membership next')
EMBED_PY
----

The returned document location includes an instance-generated identifier. Never
guess a filename or reuse one copied from another learner's output.

== Verify: Inspect workspace membership

[source,bash,role="execute"]
----
curl -fsS "$ANYTHINGLLM_URL/api/v1/workspace/$WORKSPACE_SLUG" \
  -H "Authorization: Bearer $ANYTHINGLLM_API_KEY" -o workspace-documents.json
python3 - <<'MEMBERSHIP_PY'
import json
from pathlib import Path
expected = set(json.loads(Path('embeddings-request.json').read_text())['adds'])
data = json.loads(Path('workspace-documents.json').read_text())
workspaces = data.get('workspace')
if not isinstance(workspaces, list) or len(workspaces) != 1:
    raise SystemExit('STOP: expected one workspace')
actual = {d.get('docpath') for d in workspaces[0].get('documents', []) if isinstance(d, dict)}
if not expected or not expected <= actual:
    raise SystemExit('STOP: uploaded policy is not embedded in this workspace')
print('PASS: every uploaded document is associated with the workspace')
MEMBERSHIP_PY
----

The returned workspace array should include your policy in its documents.
Membership after the embedding request prepares the next test; neither alone proves
that an answer used that document.

== Troubleshooting

* HTTP 401/403: check your learner-instance API key; do not use a platform model key.
* Upload fails: confirm the local file and workbench document processor are available.
* Embedding fails: ask the lab owner to inspect the native embedding model and storage.
* Workspace appears empty: confirm the returned slug and returned document locations.

== Takeaway

You can trace a policy from its source file to the library and workspace.
Next, require both a source citation and the distinctive policy fact in an answer.
