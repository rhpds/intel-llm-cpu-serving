= Query with RAG
:navtitle: 6. Query with RAG

_Estimated time: 15 minutes_

The business question is whether the assistant can answer from an approved
policy rather than inventing one. Use the fictional Northstar document from
Module 5 to make that distinction visible.

== Know: Follow the evidence

The workbench embeds the question, retrieves relevant chunks, adds those chunks
to the prompt, and calls the assigned model. The model does not search the
vector database itself. A fluent answer is useful only when its facts agree
with the retrieved source.

== Do: Ask for a policy fact

Keep the same Terminal, private evidence directory, and workspace slug from
Module 5. In the browser, open the workspace you just created and ask:

----
According to the Northstar workshop policy, what is the approval code for a learning-day request?
----

Repeat through the API in query mode. Query mode limits answering to workspace
context; inspect its sources as well as its answer.

[source,bash,role="execute"]
----
curl -fsS -X POST "$ANYTHINGLLM_URL/api/v1/workspace/$WORKSPACE_SLUG/chat" \
  -H "Authorization: Bearer $ANYTHINGLLM_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"message":"According to the Northstar workshop policy, what is the approval code for a learning-day request?","mode":"query"}' \
  -o grounded-answer.json
python3 - <<'ANSWER_PY'
import json
from pathlib import Path
data = json.loads(Path('grounded-answer.json').read_text())
answer = data.get('textResponse', '')
sources = data.get('sources')
if data.get('error') or data.get('type') == 'abort' or not isinstance(answer, str) or 'CEDAR-742' not in answer:
    raise SystemExit('STOP: the answer did not return the expected policy fact')
if not isinstance(sources, list) or not any(isinstance(s, dict) and 'northstar-policy' in str(s.get('title', '')).lower() for s in sources):
    raise SystemExit('STOP: no citation to the uploaded Northstar policy')
print('PASS: expected policy fact and uploaded-policy citation returned')
ANSWER_PY
----

Open the citation in the UI and compare the source passage with the answer.
The automated check establishes a fact and citation, not general answer accuracy.
Repeat the question in a fresh chat and record whether it remains grounded.

== Do: Compare without retrieved context

[source,bash,role="execute"]
----
curl -fsS "$MAAS_ENDPOINT/v1/chat/completions" \
  -H "Authorization: Bearer $MAAS_API_KEY" \
  -H 'Content-Type: application/json' \
  -d "{\"model\":\"$MAAS_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"What is the Northstar workshop learning-day approval code?\"}],\"max_tokens\":128}" \
  -o direct-answer.json
python3 -m json.tool direct-answer.json
----

A direct answer has no access to the uploaded document. Record what happened;
do not assume the direct answer must be wrong or that RAG always wins. The
important difference is access to a verifiable source, not fluency or model size.

== Do: Test missing evidence

Ask in a fresh workspace chat: "What is Northstar's monthly remote-work allowance?"
The policy does not define one. A defensible response says the evidence is
missing. If it invents an allowance, record the failure and discuss refusal
settings and source coverage. Do not mark this test passed from a citation alone.

== Record your evidence

* Source/version: Northstar workshop policy LAB-2026-10.
* Expected fact and source citation returned: ___
* Repeated grounded response agreed with source: ___
* Direct-model response and its limitations: ___
* Unsupported question declined, or failure recorded: ___
* Customer decision: which approved documents and ownership would be needed? ___

Keep response files local to this learner session. Do not publish keys, access
URLs, or customer documents. Unset the API key when finished:

[source,bash,role="execute"]
----
unset ANYTHINGLLM_API_KEY
----

== Takeaway

RAG gives a model access to evidence. You still need to check retrieval,
factual agreement, and behavior when evidence is absent before using it for
an HR workflow.
